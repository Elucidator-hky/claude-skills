# 我怎么配置 Claude Code 来管理个人的一切

我把工作、生活、找资料、整理文件都交给 Claude Code 处理。用了几个月，沉淀出一套组织方式，核心就一句话：**Claude 每次对话都从零开始，文档就是它的记忆，所以文档要分层、要可信、要按需读。**

## 一、四层结构

| 层 | 放什么 | 什么时候被读 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 行为规则 + 目录地图 + 详细文档索引 | 每次对话自动加载 |
| 详细文档（环境手册等） | 工具、账号、脚本、已知问题 | Claude 需要时按索引去读 |
| skill（`~/.claude/skills/`） | 某类任务的完整流程和踩过的坑 | 任务匹配 description 时加载 |
| memory | 对话中学到的偏好和项目背景 | 自动召回 |

每层只放该层的东西。CLAUDE.md 每轮都占上下文，所以只放规则和索引，具体内容一律下沉。

## 二、CLAUDE.md：规则少而硬

我的全局 CLAUDE.md 只有三块：

1. **规则**，每条一句话说清，比如：
   - 回答先说本质和最直接的做法
   - 不懂的先查，确定了再汇报，查不清就明说
   - 用户说了「做 / 改」才动手，其余只给结论和方案
   - 改配置前读现状，装软件前 `which`，删东西前确认没人在用
   - 多步骤任务做完一步停下确认；跑通的流程和踩的坑写进项目文档
2. **目录地图**：家目录下每个顶层文件夹是干什么的，让 Claude 知道东西该去哪找、该放哪。
3. **详细文档索引表**：文档路径 + 一句话说明里面有什么。

**写法上最有用的一条：只写正面要求，只写现在对的做法。** 「不要做 X」会让模型注意力落在 X 上；写成「做 Y」更稳。过时的做法直接删，不留「以前是这样，现在改了」。

## 三、环境手册：本机能力的唯一总索引

一份 `环境手册.md`，回答「这台电脑上 Claude 能用什么」：

- **总树**：配置、脚本、项目、密钥各在哪个目录
- **脚本清单**：每个脚本一行，名字 + 干什么 + 怎么接入（alias / hook / skill 调用）
- **AI 通道主备**：主力挂了用哪个备用
- **MCP 和插件清单**
- **场景 × 能力矩阵**：「联网搜索用什么」「视频转文字用什么」「网页操作用什么」，Claude 碰到一类任务先查这张表
- **密钥台账**：只记每个 key 存在哪个文件、控制台在哪、怎么换，不记 key 本身

三条维护规则：

1. **一个事实只写一处**，手册只放索引和一句话，深内容进各自的文档或 skill
2. **只写测过的**
3. **用前先查，有就直接用；和实际不一致就当场改正；新装的工具当场登记**——这条写进 CLAUDE.md，让 Claude 自己维护手册

## 四、skill：把「做过一次的事」变成「下次直接会」

- **一份源文件，放用户级目录** `~/.claude/skills/<name>/`。所有项目自动可见，在哪个项目里改都是改这一份。只有会在别的项目误触发、或含项目私密内容的，才放 `<项目>/.claude/skills/`
- **description 写清触发条件**：什么时候用、和相近的 skill 怎么分工。它是唯一的「路由」手段，平时上下文里每个 skill 只占这一行
- **正文写坑，不写教程**：模型本来就会的不用写。值得写的是实测出来的东西——哪个接口有签名校验、哪个参数缺了会 412、哪条路已经走不通
- **边用边追加**：每次踩到新坑，让 Claude 当场写回 skill

判断一件事该不该做成 skill：同类任务第二次出现，且第一次花了时间试错。

## 五、几个实测有用的小配置

- **UserPromptSubmit hook 每轮注入当前时间**：Claude 写日期、算「下周」不再出错
- **Stop hook 发系统通知**：长任务跑完能离开电脑
- **状态栏显示上下文用量**，到 60% / 80% 提醒 `/compact`
- **付费 API key 会静默失效**（余额用完只返回 403），写一个探活脚本把所有通道跑一遍，定期跑
- **会启动 Claude 的目录用英文命名**：会话目录名会把路径里的非 ASCII 字符逐个换成 `-`，同层字数相同的中文目录名会撞到同一个会话目录，历史对话互串
- **装插件前先看成本**：`claude plugin details <插件>@<市场>` 能看到常驻上下文开销，同等能力优先选纯 skill / CLI，MCP 的 schema 更占上下文
